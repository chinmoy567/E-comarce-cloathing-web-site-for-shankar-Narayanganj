================================================================================
                              KEY FEATURES
================================================================================

✅ Non-Blocking Errors
   If BD Courier API is unavailable, the order is NOT blocked.
   Admin/Manager can retry with forceRefresh: true.

✅ Smart Caching
   Results cached by customer_id (phone number).
   Reused across all orders for same customer within 5-minute window.
   Each check records which order triggered it (order_id in DB).

✅ Phone Number Validation
   Supports Bangladesh format: 01XXXXXXXXX
   Converts +880XXXXXXXXX to 01XXXXXXXXX
   Converts 880XXXXXXXXX to 01XXXXXXXXX
   Strips spaces and dashes

✅ Risk Level Calculation
   0-39 points   → LOW RISK
   40-69 points  → MEDIUM RISK
   70-100 points → HIGH RISK
   NULL score    → UNKNOWN

✅ Comprehensive Audit Trail
   Every risk check logged with:
   - User who initiated check (actor_id)
   - Order that triggered check (order_id)
   - Customer checked (customer_id)
   - Risk result (HIGH/MEDIUM/LOW/UNKNOWN/CHECK_FAILED)
   - Timestamp

✅ Graceful Error Handling
   API Unavailable    → riskLevel: CHECK_FAILED, continue
   No Delivery History → riskLevel: UNKNOWN, continue
   Invalid Phone      → Validation error, non-blocking
   Rate Limited       → Cached result or retry after 5 min
   Timeout (10s)      → Returns error, order continues
